# Critères de scoring ASO

Scorer chaque dimension de 0 à 10 en utilisant les grilles ci-dessous.
**Appliquer les ajustements de palier de maturité de marque** de la Phase 1.5 du skill principal.

---

## Ajustements de maturité de marque (à appliquer à toutes les dimensions)

Avant de scorer, déterminer le palier de l'app : **Dominant**, **Établi** ou **Challenger**.

**Apps Dominantes (Instagram, Uber, Spotify, WhatsApp, Netflix) :**

- Les titres marque-seule scorent 8+ (la marque EST le mot-clé)
- Les captures lifestyle/de marque scorent comme les captures d'UI avec légende
- Les Nouveautés génériques à une cadence hebdomadaire+ scorent 8+
- L'absence d'in-app events pour les apps utilitaires n'est pas une pénalité
- La description est scorée sur la qualité de conversion uniquement, pas la présence de mots-clés
- La localisation est scorée relativement à l'empreinte marché réelle
- L'absence de vidéo de présentation est acceptable si la notoriété de marque est quasi universelle

**Apps Établies (Duolingo, Strava, Notion, Calm, Cash App) :**

- Les titres marque-d'abord avec 1-2 mots-clés scorent normalement
- Les choix stratégiques de description/visuels bénéficient du doute
- Toutes les autres dimensions sont scorées normalement

**Apps Challenger (la plupart des apps) :**

- Scorées strictement à l'aune de l'ASO du manuel — chaque caractère et chaque fonctionnalité compte

**Principe clé :** avant de retirer des points, se demander : « Est-ce une erreur ou un choix
guidé par les données d'une équipe qui a plus d'informations que moi ? »

## 1. Titre et sous-titre (pondération : 20%)

**Grille Challenger :**

| Score | Critères                                                                                                                                                                |
| ----- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 9-10  | Marque + mot-clé à forte valeur dans le titre, mots-clés complémentaires dans le sous-titre, pas de répétition de mots entre champs, usage des caractères proche du max, communique instantanément l'objectif de l'app |
| 7-8   | Bonne présence de mots-clés, léger gaspillage de caractères (5+ inutilisés), objectif clair                                                                            |
| 5-6   | A des mots-clés mais mauvais placement, quelques répétitions entre champs, objectif plutôt clair                                                                       |
| 3-4   | Le titre est marque-seule ou générique, sous-titre manquant ou faible, mauvais usage des caractères                                                                    |
| 1-2   | Pas de stratégie de mots-clés, le titre ne communique pas l'objectif, gros gaspillage de caractères                                                                    |
| 0     | Impossible à évaluer (données indisponibles)                                                                                                                           |

**Ajustement Dominant/Établi :** les titres marque-seule (ex : « Instagram ») sont
valides si la marque a un fort volume de recherche. Scorer 8+ pour les apps Dominantes où
la reconnaissance de marque élimine le besoin de mots-clés génériques. Évaluer si les
caractères inutilisés représentent un gaspillage ou une simplicité intentionnelle.

**Vérifier :**

- Caractères utilisés vs limite (titre : 30, sous-titre/desc. courte : 30/80). « Proche du max » = à 3 car. de la limite (27+/30, 77+/80)
- Mot-clé principal dans le titre
- Duplication de mots-clés entre titre et sous-titre
- Si l'objectif de l'app est immédiatement clair
- Mots inutiles (articles, prépositions) consommant de l'espace
- Caractères spéciaux ou affirmations (« #1 », « best ») qui risquent un rejet (Apple)

## 2. Description (pondération : 15%)

### Apple App Store

| Score | Critères                                                                                                                                               |
| ----- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 9-10  | Les 3 premières lignes accrochent avec une proposition de valeur claire, structurée avec features/bénéfices/preuve sociale/CTA, texte promotionnel activement utilisé, convaincante et scannable |
| 7-8   | Bonne ouverture, structure correcte, pourrait améliorer la scannabilité ou le CTA                                                                     |
| 5-6   | Ouverture générique (« Bienvenue dans... »), un peu de structure, manque de CTA ou de preuve sociale                                                  |
| 3-4   | Mur de texte, pas de proposition de valeur claire au-dessus de la ligne de flottaison, pas de texte promotionnel                                      |
| 1-2   | Description minimale ou passe-partout, aucun effort                                                                                                   |
| 0     | Impossible à évaluer                                                                                                                                  |

### Google Play

| Score | Critères                                                                                                                                     |
| ----- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| 9-10  | Mots-clés dans les 3 premières phrases, 2-3% de densité naturelle dans l'ensemble, formatage HTML utilisé, sections structurées, CTA fort, mots-clés naturels |
| 7-8   | Bonne présence de mots-clés, un peu de structure, densité légèrement décalée (1-2% ou 3-4%)                                                 |
| 5-6   | Mots-clés présents mais clairsemés (<1%) ou bourrés (>5%), structure faible                                                                 |
| 3-4   | Pas de stratégie de mots-clés visible, mauvais formatage, mur de texte                                                                      |
| 1-2   | Description minimale, pas de mots-clés, pas de structure                                                                                    |
| 0     | Impossible à évaluer                                                                                                                        |

**Vérifier :**

- Qualité des 3 premières lignes (visibles avant « Lire la suite »)
- Cadrage feature-bénéfice (pas seulement des listes de features)
- Preuve sociale (téléchargements, récompenses, mentions presse)
- Appel à l'action
- Densité de mots-clés (Google Play uniquement — compter mots-clés cibles / total de mots)
- Usage du formatage HTML (Google Play)
- Présence et qualité du texte promotionnel (Apple)

## 3. Visuels (pondération : 25%)

| Score | Critères                                                                                                                                                                      |
| ----- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 9-10  | 8-10 captures avec message/légendes clairs, vidéo de présentation présente, les captures racontent une histoire en séquence, chacune communique un bénéfice, l'icône est distinctive et mémorable |
| 7-8   | 6-7 captures avec légendes, bonne icône, pas de vidéo OU bonne vidéo mais message de certaines captures peu clair                                                            |
| 5-6   | 5+ captures mais légendes faibles/absentes, icône basique, pas de vidéo, captures = dumps d'UI                                                                               |
| 3-4   | 3-4 captures, pas de légendes, icône générique, pas de storytelling                                                                                                          |
| 1-2   | Moins de 3 captures, ou captures = UI brute non éditée, mauvaise icône                                                                                                       |
| 0     | Impossible à évaluer                                                                                                                                                         |

**Vérifier :**

- Nombre de captures (minimum 5, idéal 8-10)
- Texte de légende/overlay sur les captures (un message par écran, 5-7 mots max)
- 3 premières captures (impact de conversion le plus fort sur Apple)
- Présence et qualité de la vidéo de présentation
- Caractère distinctif de l'icône (pas de texte dans l'icône, formes marquées, se démarque)
- Présence de la feature graphic (Google Play — obligatoire pour les placements en avant)
- Flux de storytelling des captures (racontent-elles une histoire cohérente ?)
- Visuels localisés (pour les marchés non anglophones)
- Mots-clés des légendes (Apple — indexés depuis juin 2025)

## 4. Notes et avis (pondération : 20%)

| Score | Critères                                                                                               |
| ----- | ------------------------------------------------------------------------------------------------------ |
| 9-10  | 4,5+ étoiles, 10K+ notes, avis récents positifs, le développeur répond aux négatifs, flux d'avis régulier |
| 7-8   | 4,0-4,4 étoiles, 1K+ notes, avis récents majoritairement positifs, quelques réponses du développeur    |
| 5-6   | 3,5-3,9 étoiles, 500+ notes, avis récents mitigés, pas de réponses du développeur                      |
| 3-4   | 3,0-3,4 étoiles, <500 notes, thèmes négatifs dans les avis récents                                     |
| 1-2   | Sous 3,0 étoiles, peu de notes, pas d'engagement du développeur, plaintes visibles                     |
| 0     | Pas encore de notes ou impossible à évaluer                                                            |

**Vérifier :**

- Note moyenne (cible : 4,0+ minimum, 4,5+ idéal)
- Nombre total de notes
- Sentiment des avis récents (5-10 derniers avis visibles)
- Thèmes de plaintes courants (bugs, crashs, prix, UX)
- Présence et qualité des réponses du développeur
- Tendance de la note (en amélioration ou en déclin, si visible)
- Récence des avis (des avis frais signalent une base d'utilisateurs active)

---

## 5. Métadonnées et fraîcheur (pondération : 10%)

| Score | Critères                                                                                                                  |
| ----- | ----------------------------------------------------------------------------------------------------------------------- |
| 9-10  | Mise à jour dans le dernier mois, 10+ localisations, choix de catégorie optimal, in-app events/LiveOps actifs, sécurité des données complète |
| 7-8   | Mise à jour dans les 2 mois, 5+ localisations, bonne catégorie, sécurité des données présente                          |
| 5-6   | Mise à jour dans les 3 mois, 2-4 localisations, catégorie acceptable                                                   |
| 3-4   | Mise à jour il y a 3-6 mois, 1-2 localisations, catégorie possiblement erronée                                         |
| 1-2   | Pas mise à jour depuis 6+ mois, langue unique, mauvais choix de catégorie                                              |
| 0     | Impossible à évaluer                                                                                                   |

**Vérifier :**

- Date et récence de la dernière mise à jour
- Nombre de langues/localisations supportées
- Sélection de catégorie (est-ce le meilleur choix ? une alternative moins concurrentielle ?)
- Présence d'in-app events (Apple) ou de contenu promotionnel (Google)
- Complétude de la section sécurité des données / étiquette de confidentialité
- Pertinence de la classification d'âge
- Qualité de l'historique des versions (les notes de version communiquent-elles de la valeur ?)
- Qualité du texte « Nouveautés »

---

## 6. Signaux de conversion (pondération : 10%)

| Score | Critères                                                                                                                                                          |
| ----- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 9-10  | Valeur claire avant le téléchargement, prix/achats intégrés transparents, preuve sociale visible (presse, récompenses), tranche de téléchargements suggérant une forte traction, crédibilité du développeur forte |
| 7-8   | Bonne communication de la valeur, prix clair, un peu de preuve sociale                                                                                           |
| 5-6   | Proposition de valeur présente mais faible, prix peu clair ou achats intégrés envahissants, preuve sociale limitée                                               |
| 3-4   | Peu clair ce que l'utilisateur obtient, prix confus, pas de preuve sociale, faibles téléchargements visibles                                                     |
| 1-2   | Pas de communication de valeur, prix suspect, app qui semble abandonnée                                                                                          |
| 0     | Impossible à évaluer                                                                                                                                             |

**Vérifier :**

- Transparence des prix (gratuit, freemium, payant — est-ce clair ?)
- Qualité de la liste des achats intégrés (les noms d'achats intégrés communiquent-ils de la valeur ?)
- Tranche de téléchargements (Google Play — 10K+, 100K+, 1M+ signalent la confiance)
- Reconnaissance du nom/de la marque du développeur
- Badges « Choix de la rédaction » ou de mise en avant
- Mentions presse ou récompenses dans la description
- Apps liées du même développeur (signal de confiance du portfolio)
- Transparence des pratiques de confidentialité

## Calcul du score final

```
Score final = (Titre * 0,20) + (Description * 0,15) + (Visuels * 0,25)
            + (Notes * 0,20) + (Métadonnées * 0,10) + (Conversion * 0,10)

Mise à l'échelle sur 100 : Score final * 10
```

**Exemple :** Titre : 7, Description : 6, Visuels : 8, Notes : 9, Métadonnées : 5, Conversion : 7

```
(7 * 0,20) + (6 * 0,15) + (8 * 0,25) + (9 * 0,20) + (5 * 0,10) + (7 * 0,10)
= 1,4 + 0,9 + 2,0 + 1,8 + 0,5 + 0,7
= 7,3 → 73/100 → Note : B
```
