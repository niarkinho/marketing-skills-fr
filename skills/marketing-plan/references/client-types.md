# Types de clients — Variations par business model

La structure du plan en 13 sections reste constante d'un type de client à l'autre. Ce qui change, c'est l'**accent de contenu** au sein de chaque section. Ce doc nomme les patterns dominants par archétype de client.

## Archétype 1 — SaaS B2B

### Caractéristiques de base
- Revenu par abonnement
- Souvent un ACV plus élevé (1K€–100K€+ par an)
- Sales-assisted ou self-serve selon le tier
- L'acheteur est souvent différent de l'utilisateur (champion vs. end-user)

### Accent AARRR

**Acquisition lourde :**
- Le SEO est la motion dominante de haut de funnel (les gens cherchent des solutions)
- Le content marketing (blog, base de connaissances, pages de comparaison) génère des MQLs
- LinkedIn pour à la fois la présence organique du fondateur et le paid
- L'outbound (cold email + LinkedIn) complète souvent l'inbound
- Les événements (conférences, webinaires) pour les produits à fort ACV

**Activation :**
- Signup → essai → première action clé (produits PLG)
- Essai → démo → POC (produits sales-led)
- Les empty states comptent — guider les utilisateurs vers la première action de valeur

**Rétention :**
- Métriques d'engagement produit (DAU, adoption de fonctionnalités)
- Motion de customer success (équipe CSM pour les ACV élevés)
- Emails lifecycle centrés sur la découverte de fonctionnalités, les moments de valeur

**Recommandation :**
- Programmes de customer advocacy
- Co-marketing partenaire / intégration
- Avis G2 / Capterra
- Expansion du champion vers l'acheteur

**Revenu :**
- L'expansion / NRR est souvent le plus gros levier de croissance
- Upgrades de tier, expansion de sièges, add-ons usage-based

### Accent skills
- `cold-email`, `programmatic-seo`, `competitors`, `seo-audit`, `ai-seo`
- `ads` pondéré vers LinkedIn + Google
- `emails` pour le nurture d'essai + lifecycle
- `pricing` pour l'optimisation de tier

### Priorité budget Tier-1
- SEO + contenu > tout le reste
- Canal LinkedIn founder-led
- Customer.io / Mailchimp pour le nurture
- HARO + backchannel investisseurs pour la RP

## Archétype 2 — App grand public D2C (abonnement)

### Caractéristiques de base
- ACV plus bas (5–30 €/mois typiquement)
- Volume élevé, marge plus faible par utilisateur
- App Store / Play Store comme surface d'acquisition principale
- Email lifecycle + push pour la rétention
- Souvent piloté par l'acquisition paid une fois le budget débloqué

### Accent AARRR

**Acquisition :**
- L'App Store Optimization (ASO) est l'asset hors-site à plus fort levier
- Paid social (Meta, TikTok) souvent dominant une fois le budget présent
- Apple Search Ads pour le trafic App Store à forte intention
- Influenceurs + créateurs de contenu
- RP + endorsements

**Activation :**
- L'onboarding est la surface d'activation dominante
- Le time-to-value doit se compter en minutes, pas en heures
- Structure du paywall + durée d'essai critiques

**Rétention :**
- Email lifecycle + push
- Rappels in-app (avec précaution — l'excès = churn)
- Centre de préférences d'abonnement
- Campagnes de win-back

**Recommandation :**
- Partage intégré (flow share-a-month)
- Recommandations bilatéraux
- Ambassadeurs influenceurs / créateurs

**Revenu :**
- Le plan annuel par défaut est le plus gros mouvement unique (compresse le MRR mais améliore la LTV)
- Optimisation de tier (Free → Premium → Premium+)
- Upsells in-app

### Accent skills
- `onboarding`, `paywalls`, `emails`
- `ads`, `ad-creative` (forte itération créative)
- `referrals`
- `pricing` pour le défaut annuel + consolidation de tiers

### Priorité budget Tier-1
- ASO d'abord (plus fort levier organique)
- Refonte de l'onboarding
- Livraison de l'email lifecycle
- Social founder-led si le fondateur est à l'aise caméra

## Archétype 3 — Hybride Hardware + Software

### Caractéristiques de base
- Produit physique + compagnon logiciel (ex : le masque de nuit + app de Quietude)
- Le hardware comme coin de distribution (prix plus bas, premier achat plus facile)
- Le software comme LTV (revenu récurrent)
- CAC blended à travers les deux surfaces

### Accent AARRR

**Acquisition :**
- SEO du storefront Shopify (les pages produit hardware ciblent la recherche grand public)
- Fiche Amazon (forte découverte, prend de la marge)
- Amplification RP (le hardware est photogénique — les endorsements d'influenceurs en vue déplacent du volume)
- Paid social pour le hardware (Meta + Instagram, créa accrocheuse)

**Activation :**
- Deux activations à suivre : expérience d'unboxing hardware + signup software
- Le flow d'activation hardware → software est le pont
- Setup concierge pour les acheteurs hardware à forte valeur

**Rétention :**
- Lifecycle post-achat hardware (différent de l'onboarding app)
- Le compagnon logiciel crée l'accroche
- Communauté / réseau de praticiens autour du hardware

**Recommandation :**
- Flows de gifting hardware (fort bouche-à-oreille pour les produits physiques)
- Le hardware accrocheur génère du partage social organique
- Avis sur Shopify + Amazon

**Revenu :**
- Le calcul de LTV blended est critique (marge hardware + récurrent software)
- Stratégie de bundle (achat hardware → Premium gratuit pendant X mois)
- Plan annuel par défaut pour le software

### Accent skills
- `seo-audit` pour les pages produit Shopify
- `emails` pour à la fois le post-achat hardware et le lifecycle software
- `referrals` avec couche gifting
- `pricing` pour le calcul de bundle-blended
- `ads` avec présence Meta forte en créa

### Priorité budget Tier-1
- Optimisation des pages produit Shopify
- Livraison du lifecycle post-achat hardware
- Formalisation de la stratégie de bundle
- Audit de l'activation hardware → app

## Archétype 4 — Marketplace

### Caractéristiques de base
- Produit bilatéral (offre + demande)
- Les effets de réseau comptent
- La liquidité est la métrique précoce critique
- Take-rate × GMV est le modèle de revenu

### Accent AARRR

**Acquisition :**
- Deux funnels — offre et demande
- L'offre est souvent acquise via outbound / partenariat / cold email
- La demande est souvent acquise via SEO / paid / contenu
- SEO programmatique ville-par-ville courant

**Activation :**
- Activation de l'offre : première annonce postée, première réponse envoyée
- Activation de la demande : premier achat / premier match / première transaction
- Les deux faces ont besoin de leur propre onboarding

**Rétention :**
- Fréquence de transaction répétée
- Utilisation de l'offre (% d'annonces actives)
- Habitude de la demande (DAU / MAU)

**Recommandation :**
- Offre → offre (référencer d'autres prestataires)
- Demande → demande (référencer d'autres acheteurs)
- Les recommandations cross-side sont plus faibles

**Revenu :**
- Optimisation du take-rate
- Tier premium (meilleur matching, frais réduits)
- Monétisation lead-gen vs. frais de transaction

### Accent skills
- `programmatic-seo` pour les pages ville, les pages verticales
- `cold-email` pour le recrutement côté offre
- `referrals` pour les deux faces
- `pricing` pour les décisions de take-rate

### Priorité budget Tier-1
- Build de SEO programmatique pour une face
- Outbound à froid pour amorcer l'offre (ou la demande, selon le goulot)
- Email lifecycle pour les deux faces

## Archétype 5 — Outil développeur / Open Source

### Caractéristiques de base
- Acheteur technique (développeur ou eng leader)
- Barre haute pour la qualité du contenu (les développeurs sont sceptiques)
- Le DevRel compte plus que le marketing traditionnel
- La couche open source funnel souvent vers le produit commercial

### Accent AARRR

**Acquisition :**
- Contenu technique + SEO de la doc
- DevRel (conférences, talks, communauté)
- Présence GitHub + découverte npm/pip/etc.
- Hacker News + Reddit + dev Twitter

**Activation :**
- Le premier build / la première intégration est l'événement d'activation
- Le time-to-Hello-World compte
- Documentation = onboarding pour les dev tools

**Rétention :**
- Profondeur d'intégration (utiliser plus du produit)
- Adoption par l'équipe (un utilisateur → toute l'org)
- Nombre de projets actifs

**Recommandation :**
- Nombre de stars sur GitHub (semi-organique)
- Recommandation dans les forums techniques
- Talks de conférence mentionnant l'outil

**Revenu :**
- Conversion free → payant quand l'usage dépasse les limites
- Plans d'équipe, tiers enterprise
- Upsells support / SLA

### Accent skills
- `programmatic-seo` pour la doc
- Moins d'accent sur les `ads` traditionnels
- Fort `content-strategy` + contenu technique
- `cold-email` vers les eng leads des entreprises cibles

### Priorité budget Tier-1
- Production de doc + contenu technique
- DevRel (le fondateur fait des talks)
- Présence GitHub
- HN / Reddit / communauté dev

## Archétype 6 — Deep-Tech / Scientifique / Clinique

### Caractéristiques de base
- Cycles de vente longs
- Lourd fardeau de crédibilité (il faut prouver la science)
- Acheteurs très informés (académiques, cliniciens, chercheurs)
- Souvent des considérations réglementaires

### Accent AARRR

**Acquisition :**
- Publication académique + études peer-reviewed
- Prise de parole en conférence (académique + industrie)
- Introductions par investisseurs / advisors
- RP via des hooks de crédibilité

**Activation :**
- Programmes pilotes / proofs-of-concept
- Setup concierge avec onboarding high-touch
- Webinaires éducatifs / formations

**Rétention :**
- Customer success fortement
- Co-publication avec les clients
- Communauté de pratique

**Recommandation :**
- Références académiques / cliniques
- Features en panel de conférence
- Études de cas avec institutions nommées

**Revenu :**
- Pilote → expansion payante
- Contrats institutionnels (multi-sièges / multi-années)
- Upsells conformité / certification

### Accent skills
- Marketing traditionnel léger
- Fort `product-marketing`, `sales-enablement`, `pricing`
- `cold-email` vers des chercheurs / praticiens précis
- RP + marketing investisseurs

### Priorité budget Tier-1
- Outreach académique + prise de parole en conférence
- Backchannel investisseurs pour des intros chaudes institutionnelles
- Déploiement pilote avec des clients clés
- Étude de cas + publication scientifique

## Archétype 7 — Commerce / DTC (hors abonnement)

### Caractéristiques de base
- Produits physiques ou digitaux vendus de façon transactionnelle
- L'Average Order Value compte
- Le taux de réachat est la métrique de rétention clé

### Accent AARRR

**Acquisition :**
- Paid social (Meta, TikTok) souvent dominant
- SEO Shopify pour les pages produit
- Fiches Amazon
- Partenariats influenceurs + créateurs

**Activation :**
- Le premier achat est l'événement d'activation
- Récupération de panier abandonné
- Signaux de confiance au checkout (avis, retours, livraison)

**Rétention :**
- Lifecycle post-achat
- Programmes de fidélité
- Email + SMS pour le réachat

**Recommandation :**
- Flows de gifting
- Programmes refer-a-friend
- Avis + UGC

**Revenu :**
- Optimisation de l'AOV (bundles, upsells)
- Optimisation de la LTV client (fréquence de réachat)
- Option d'abonnement pour les achats récurrents

### Accent skills
- `ads` + `ad-creative` (forte pondération)
- `emails` pour le post-achat + panier abandonné
- `referrals` avec gifting
- `pricing` pour les bundles + option d'abonnement

### Priorité budget Tier-1
- Optimisation du storefront Shopify
- Livraison du lifecycle email
- Seeding d'influenceurs / UGC
- Test de paid social (si un budget minimal existe)

## Comment utiliser ce doc en rédigeant un plan

Quand vous commencez à rédiger les Sections 4–8 (AARRR), identifiez l'archétype du client (ou hybride le cas échéant) et appuyez-vous sur les patterns ci-dessus.

**Les cas hybrides sont courants.** Quietude est « Hybride hardware + software » avec un fort recouvrement avec « Deep-tech / scientifique / clinique » (à cause de l'étude peer-reviewed + du positionnement clinique). Le plan mélange les accents des deux archétypes.

En cas de doute, mener avec l'archétype qui correspond le mieux au *modèle de monétisation principal*. La monétisation principale de Quietude est l'abonnement software (avec le hardware comme coin), donc les patterns app grand public D2C + hardware-hybride dominent, avec des mouvements de crédibilité deep-tech superposés.

## Quand le client ne rentre pas proprement

Certains clients défient l'archétype :
- **Business de contenu / média** — ni SaaS ni commerce ; modèle de revenu pub ou abonnement
- **Réseaux sociaux** — catégorie propre, les effets de réseau dominent
- **Immobilier / événements** — modèle physique + service

Pour ceux-là, identifier l'archétype le plus proche et ajuster. Ne pas forcer — nommer la déviation dans le Cadre Stratégique du plan.
